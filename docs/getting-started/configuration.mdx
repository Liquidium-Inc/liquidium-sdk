# Configuration

Create the client with defaults for Liquidium mainnet:

```ts
import { LiquidiumClient } from "@liquidium/client";

const client = new LiquidiumClient();
```

Pass config when your app needs custom transports, headers, canister IDs, or EVM read support:

```ts
const client = new LiquidiumClient({
  apiBaseUrl: "https://app.liquidium.fi/api/sdk",
  headers: {
    "x-client-name": "my-app",
  },
  evmRpcUrl: import.meta.env.VITE_EVM_RPC_URL,
});
```

## Config Fields

| Field | Use |
| --- | --- |
| `environment` | Select bundled canister IDs. The SDK currently bundles only `"mainnet"`. |
| `icHost` | Override the ICP replica host. |
| `identity` | Send signed canister calls with a caller identity. |
| `apiBaseUrl` | Override the Liquidium SDK HTTP API root. Defaults to `https://app.liquidium.fi/api/sdk`. |
| `headers` | Add headers to SDK HTTP API requests. |
| `canisterIds` | Partially override `lending`, `ethDeposit`, `simpleLoans`, or `pools.{btc,eth,usdt,usdc,icp}` for custom deployments. |
| `fetch` | Provide a custom fetch implementation. |
| `timeoutMs` | Set the SDK API request timeout in milliseconds. Defaults to `30_000`. |
| `evmRpcUrl` | Create a viem public client for public ERC-20 reads and best-effort native ETH outflow checks. |
| `evmRpcHeaders` | Add headers to EVM RPC requests. |
| `evmPublicClient` | Use an existing viem-compatible read client with `readContract`. An optional `getCode` method enables best-effort native ETH outflow checks through that client. When supplied, it takes precedence over `evmRpcUrl` and `evmRpcHeaders`. |

Use nested canister overrides:

```ts
const client = new LiquidiumClient({
  canisterIds: {
    lending: "aaaaa-aa",
    simpleLoans: "u5rm3-niaaa-aaaar-qb7eq-cai",
    pools: {
      btc: "bbbbb-bb",
      eth: "ccccc-cc",
    },
  },
});
```

Removed flat keys such as `instantLoans`, `btcPool`, and `ercPool` are rejected with `LiquidiumErrorCode.VALIDATION_ERROR`.

Set `VITE_INFURA_API_KEY` or `VITE_EVM_RPC_URL` when you run an example that needs Ethereum reads.

Native ETH lending borrow and withdrawal flows check destination bytecode through a configured EVM client with `getCode`. When no bytecode-capable EVM client is configured, the SDK uses the Liquidium SDK API instead. A confirmed deployed contract is rejected with `LiquidiumErrorCode.CONTRACT_DESTINATION_UNSUPPORTED`. Prepared lending actions check before signing and again on submission. The zero address and Ethereum mainnet precompile addresses are rejected with `LiquidiumErrorCode.INVALID_ADDRESS`.

This check prevents a known native ckETH withdrawal failure mode. The ckETH minter [fixes native ETH withdrawals at 21,000 gas and warns that smart-contract destinations will likely fail](https://github.com/dfinity/ic/blob/0f3c60f6a7ba51e3306c2305072a2959b00718ef/rs/ethereum/cketh/minter/cketh_minter.did#L751-L762). The minter uses a separate 65,000-gas ERC-20 transfer path for ckERC20 withdrawals, so the SDK does not apply this destination check to USDC or USDT outflows.

Bytecode validation is intentionally best-effort and fails open. If the configured RPC or SDK API is absent, unavailable, times out, or returns a malformed response, the SDK allows the native ETH outflow to continue rather than turning an advisory compatibility check into an availability dependency. Custom `apiBaseUrl` deployments may implement `GET /v2/ethereum/addresses/:address/bytecode`, but its absence does not block an outflow.

The check proves only that code was deployed at the block queried by the RPC provider. It cannot identify counterfactual ERC-4337 or CREATE2 accounts before deployment, and state can change after any off-chain check.
